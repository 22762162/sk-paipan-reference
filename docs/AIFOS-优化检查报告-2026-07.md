# AIFOS V3.2 优化检查报告 —— 对照 2026 主流漫剧生产管线

- **审计对象**：分支 `claude/sk-manga-drama-platform-b8nbe3` @ `5b64f42`（2026-07-26），`aifos/` 约 3.5 万行
- **审计方式**：三路并行代码审计（管线/成本调度、角色一致性/出图、声画/剪辑/发布/回流）+ 主流漫剧管线联网调研
- **行业基准**：2026 主流 7 层流水线（网文采集 → 章节切片 → 结构化分镜 → 角色资产库 → 出图 → 动态化/配音 → 分发+数据回流），头部单集成本 ¥3.2–40，角色一致性为 72% 创作者第一痛点

---

## 〇、总体结论

**AIFOS 的前段与治理明显超出行业主流水平，后段基本是空的，一致性技术底座停留在 prompt 层。**

- **超出主流的部分**：母资产四视图体系（审核板 + closeup/front/profile/back 独立母资产）、参考图逐图互斥职责分离、17 列镜头合同 + 15 项开拍门禁、fail-closed 视觉质检、防盲目重试（输入未变禁止原样重调）、系统性漂移熔断（≥3 张同类身份问题即停批）、规则四层分级治理 + 唯一优先级、制作标准不可变版本 + 逐集快照。这套"生产合同化"在公开的同类产品里属于第一梯队。
- **与主流的硬差距**：视频生成之后——混音、字幕、成片渲染、分发、数据回流——几乎全靠人工；一致性缺 seed / 相似度量化 / 权重级绑定三样行业成熟手段；AIGC 标识合规为零。
- **另发现 8 个真实缺陷/隐患**（见第三节），其中"字幕轨必须为空"硬规则实际未被质检覆盖、并行路径预算熔断被绕过、成本按 Provider 统计失效三项建议尽快修。

| 主流管线层 | AIFOS 现状 | 评价 |

## 二、优化清单（按优先级）

### P0 —— 修了立刻见效 / 合规必须

**1. AIGC 标识与平台审核预检（合规硬缺口）**
全仓无任何 AIGC 显式标识、元数据标记或平台审核预检；敏感词库只有 3 个硬编码词的子串匹配（`config.py:87`）。抖音/红果已强制 AIGC 内容标识，发布被拒的返工成本最高。建议：publish 包内加 AIGC 标识声明 + 可配置合规词库 + 发布前预检清单。

**2. 固定 seed（改动最小的一致性增强）**
Seedream/OpenAI 请求体均无 `seed` 字段（`api_providers.py:816-822, 566-579`）。同一角色每次生成都是独立采样，重画不可复现，无法"锁 seed 只改提示词"做受控微调。改动仅为 API 加一个字段 + 存进资产 meta。

**3. 人脸相似度量化打分 + best-of-N**
目前身份核验只有 VLM 二值 `identity_match: true/false`（`codex_image.py:490-495`），阈值刻意从宽、自动重试硬限 1 次（`director.py:2523-2531`）——一致性最终判断实际压给人工目检，规模化时人工是瓶颈。建议接一个轻量人脸 embedding（余弦相似度对母资产打分），直接挂到现有 `identity_match` 位置，即可量化"第 40 镜比第 1 镜漂了多少"并自动 best-of-N。

**4. 视频自动分级 + 静态动效降级（最大的成本杠杆）**
每个镜头无条件走 Seedance 首尾帧生视频（`director.py:7804`），`resolve_video_quality` 的 `auto` 恒返回 medium（`quality_policy.py:189`）——图片侧有自动分档（`recommend_shot_image_quality`），视频侧没有。行业主流只对 20–30% 关键镜头上视频模型。建议：
- 复用图片侧启发式给视频自动升降档（关键镜 1080p、普通镜 720p、低动态镜 480p）；
- `beat`（情绪留白 2–4 秒）和 `reaction`（听者反应镜）这两类系统自己生成的低运动镜头，可用关键帧+轻微推拉合成，省掉整档 Seedance 调用——这两类镜头当前与主镜同价。

**5. 字幕数据直出（保留无字幕母版，但要出字幕轨数据）**
"无字幕母版"是有意为之的硬规则，可以保留；问题是系统连字幕**数据**都不产出：无 SRT/VTT 导出（全仓零命中），剪映草稿只建一条空文本轨（`jianying_draft.py:106`），台词要人工重新打字。台词文本系统里全都有——从台词直出 SRT + 剪映文本轨（含漫画体样式预设）几乎零成本，砍掉整个人工打字幕环节。

**6. 修复"字幕轨必须为空"的质检盲区（真实隐患）**
`production/jianying_draft.py:133-138` 在 `dialogue` 存在时会无视 `forbid_subtitles` 写入 `TextSegment`（该参数在此文件从未被读取）；而 `qc_center.py:246-256` 只查 `ctx["subtitles"]` 和 `edit_data.tracks.subtitle`，剪映 provider 返回值根本没有 `tracks` 字段——硬规则在真实产线上没有被质检覆盖，目前仅因 payload 恰好无 `dialogue` 键而未触发。

### P1 —— 后段链路补齐（对照主流的主要缺口)

**7. 声音设计从"一层"到"多层"**
现状只有 Seedance2 内置人声一层；`sound_design` 三元组只进提示词、不产出任何音频文件（`workflow.py:1110-1118`）；BGM 被硬规则禁止（`standard_center.py:322` `no_bgm: True`）；无 volume/ducking/LUFS 概念；声音门禁只判 `environment` 字段非空，而该字段由 f-string 无条件生成——**这是一个永真的空门**（`qc_center.py:191-197` + `workflow.py:1110`）。行业主流是四层音轨（人声/环境/情绪音效/BGM，BGM 压人声 30–50%）——成片"AI 味"重的主因之一就是缺后三层。建议至少在剪映草稿里预铺 BGM/音效轨位 + 音量预设，或母版渲染时做 loudnorm。

**8. 成片自动渲染**
`edit` 能力只有 jianying/mock（`config.py:216`），产物是草稿目录，成片必须人工开剪映点导出（`jianying_draft.py:162`）；转场写死"硬切"且全仓无消费者（`workflow.py:1204`）。加一条 ffmpeg 渲染路径（镜头拼接 + 交叉溶解/黑场 + 音轨混合 + 字幕可选烧录），"一句话开工"才能真正出 mp4。

**9. 运营包装 LLM 化 + 拆条真切片**
标题是 f-string 模板（`ops_center.py:36-57`，注释自认待做）；话题标签硬编码 4 个（`ops_center.py:88-93`）；拆条只写 JSON 描述文件不切视频（`ops_center.py:59-85`）。标题/文案路由到 script 能力的 LLM、拆条接 ffmpeg 切片，都是现成管道的小改动。

**10. 数据回流闭环（从"只出不回"到反哺选题）**
`archive` 表 15 处写入、读取方只有 JSONL 导出和 stats，`cases()` 全仓无调用者（`data_center.py:23`）；完播率/掉点/分账相关字段与表结构零命中。`lessons.py` 是唯一真实反馈闭环但只回流"画错了"，不回流"没人看"。建议：加一张 `episode_metrics` 表（人工粘贴或后续接开放平台），把完播率/掉点秒数关联到镜头级（分镜结构化的红利），回灌选题与钩子设计——这是主流"生产系统"与"生成器"的分水岭。

### P2 —— 性能与工程债

**11. 并发与轮询**（详见审计，按影响排序）：
- `_ensure_spatial_reference_assets` 每镜全量重算 → O(N²) DB 查询（`director.py:7878` 调 `7833`），应在 `_stage_videos` 入口算一次；
- 视频 payload 主线程串行预备完才提交第一个 worker（`director.py:7804-7821`）；
- `_cancel_requested` 无缓存 DB 轮询，dreamina 每 0.5s 一查，4 路并发 = 8 次/秒空转（`dreamina.py:217-221`、`director.py:970-973`）；
- 单镜视频失败即不再派发整批剩余镜头（`director.py:8861-8876`），应与图片侧 `continue_on_qc_failure` 对齐；
- 首尾帧场内强制串行（`director.py:7614-7761`），长场景把 24 路并发压成 1 路；
- QC 循环每轮重跑 `_stage_edit`，草稿名带时间戳，草稿库堆积垃圾（`director.py:9791`、`jianying_draft.py:96`）。

**12. 成本记账修复**：
- `cost_by_provider` 按逗号拼接字符串分组，多 Provider 阶段成本计给假 Provider（`system_center.py:88-92`）；
- 并行路径只在整批开始前查一次预算，worker 直接 `router.call` 绕过 `_call` 的熔断（`director.py:3742-3746, 8808-8812`）；
- `_refresh_design_from_reference` 直接 `router.call` 不记账（`director.py:12758`）；
- 有逐次 `attempt_history` 原始数据但无跨镜/跨集聚合——无法回答"这一集平均每镜抽几次卡"（行业衡量资产库质量的核心体温计）。

**13. quota 与复用判定**：
- quota `used` 只增不减，无月度重置接口，订阅刷新后 jimeng 会被永久判死、静默全量回退到更贵的 API（`router.py:77-98`）；4 路并发下查减之间有 TOCTOU 竞态可超发；
- **视频复用判定最松（只查文件存在，`director.py:7806`）但视频最贵**；已有的 `input_signature`（`director.py:8710-8723`）未用于复用判定——改参考图不改分镜会静默复用旧视频；
- 交付复核脚本不校验实际分辨率，720p 素材声称交付 1080×1920 无人拦截（`workflow.py:1773-1776`），剪映画布按 1080×1920 拉伸且全链无超分。

**14. 一致性周边补强**：
- 画风基准图无自动兜底：用户不手动标注 `role=style` 就返回 `None`，画风只剩文字在撑（`director.py:1114-1133`）；且 `director.py:5735` 注释与实现已脱节；
- 服装无母资产定版闭环（人物/场景/道具都有 candidate→identity，服装只有逐镜文字状态 + 临时挑图 `director.py:6244`），是跨集一致性最可能先崩的维度；
- 帧链复用（首帧=上一镜尾帧 `codex_image.py:284,305`）缺周期性回锚立绘的校正点，上游轻微漂移会沿链无损传播整场；
- `cast_dedup` 是 LLM 文字自评，缺候选图之间的图像相似度交叉校验。

**15. 文档与分支收尾**：
- README 与代码漂移：实际 15 阶段/15 门禁，README 写 14（漏 `spatial_seedance` 门，`workflow.py:1570-1637` vs `README.md:129-135`）；
- 两个未合并分支待处理：`codex/prop-policy`（道具资产前置，2 commits）、`codex/video-aspect`（Seedance 画幅可选，1 commit）。

## 三、投入产出排序建议

| 顺序 | 事项 | 改动量 | 收益 |
|---|---|---|---|
| 1 | 修质检盲区（#6）+ 成本记账三处（#12） | 小 | 消真实隐患 |
| 2 | 固定 seed（#2） | 极小 | 重画可复现、受控微调 |
| 3 | 字幕 SRT/剪映轨直出（#5） | 小 | 砍掉人工打字幕环节 |
| 4 | AIGC 标识 + 合规词库（#1） | 小 | 发布合规兜底 |
| 5 | 视频自动分档 + beat/reaction 静态降级（#4） | 中 | 单集成本最大杠杆 |
| 6 | 人脸相似度打分 best-of-N（#3） | 中 | 一致性量化、解人工瓶颈 |
| 7 | ffmpeg 成片渲染 + 转场（#8） | 中 | 真正端到端出片 |
| 8 | 四层音轨/BGM 轨位（#7） | 中 | 去"AI 味"最便宜的观感提升 |
| 9 | episode_metrics 数据回流（#10） | 中 | 生成器 → 生产系统 |
| 10 | 并发/轮询/quota 工程债（#11 #13） | 中 | 吞吐与稳定性 |
