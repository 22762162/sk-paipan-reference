# AIFOS 规则治理与生产流程

## 目标

规则只在自己的范围内生效。一次质检失败不得自动变成跨项目、跨剧集或
跨镜头的永久提示词。遇到冲突时，系统按唯一优先级裁决，而不是把两条
互斥指令一起发送给模型。

## 唯一优先级

1. 用户已经锁定的事实或逐项人工修订
2. 本集正式剧本、制作圣经与人物定版
3. 当前镜头合同
4. 本集制作标准快照、质量策略与人物资产策略
5. Provider 能力边界
6. 系统默认和旧数据兼容回退

低优先级只能补缺，不能覆盖高优先级事实。Provider 只能验证、执行或
阻断，不能静默改人物、参考图、质量或生产规格。

## 四类规则

| 范围 | 可以包含 | 生命周期 | 是否进入其他镜头 |
|---|---|---|---|
| 系统永久规则 | 身份、性别、人数、物理、文字白名单、参考图绑定、文件完整性 | 永久 | 是 |
| 项目/本集事实 | 时代、画风、服装、道具、允许的跨时代物件 | 项目或本集结束 | 仅同项目/本集 |
| 当前镜头合同 | 机位、构图、动作、站位、起止状态 | 镜头版本变化即失效 | 否 |
| 一次性修复规则 | 本次提示词补丁、参考图调整 | 通过或自动修复一次即失效 | 否 |

质检发现的问题先进入“待审核观察库”，不自动写入永久规则。确实需要
跨镜头复用时，必须由人工明确批准适用范围并形成新版本。

## 强制门禁与导演建议

身份、性别、人数、连续性、物理空间、文字、参考图输入合同、首尾帧、
声音和实际生产规格是系统永久硬门，不能关闭或降成警告。

反应镜数量、景别跳级、机位变化等创作启发属于导演建议。建议会出现在
报告中，但不扣质检通过分，也不阻断一条有明确导演意图的镜头。

## 镜头合同版本治理

当前写入版本为 `aifos.shot-prompt/v2.1`。系统对旧 v2 合同采用“宽读
严写”策略：可以读取并确定性补齐旧字段，但重新编译、修复、重试、保存或
发起正式生成时只允许输出 v2.1。兼容回退不能覆盖明确的新字段，也不能
降低 v2.1 硬门禁。

旧 v2 没有 `functional_figures` 时，功能人物数为 0，总可见人数默认等于
登记人物数；`subject.count` 继续保留为登记人物数的兼容别名。v2.1 的
规范人数来源是 `population.counts`，`subject.registered_count` /
`functional_count` / `visible_count` 是迁移期直观别名。这个默认只适用于
字段确实不存在的旧镜头。一旦镜头显式提供功能人物或总可见人数，三项人数
必须精确一致，不得退回旧行为掩盖错误。

## v2.1 人数治理

人物数量使用三个独立概念，并在 `population.counts` 中分别记录：

- 登记人物 `named_characters`：`characters` 中有稳定身份、需要连续性
  比对的角色；
- 功能人物 `functional_people`：仅承担本镜剧情或构图功能、仍真实可见
  的人形，例如黑衣人、
  书童尸体、守卫背影；
- 真实总人数 `real_people_total`：登记人物数加所有功能人物精确数量。

非现实 Q 版等实例单独进入 `non_real_overlays`，所有真实人形与非现实
叠层的可见实例和进入 `visible_entity_instances_total`。真实人数门禁只与
`real_people_total` 和构图可见人形数比较，不能把 Q 版叠层误算成真人。

功能人物的 `count` 必须是明确的正整数。“几名”“数名”“若干”、范围值、
空值和推测值在导入阶段可以作为待修订问题，但不具备生产资格。构图合同的
可见人数、提示词中的总人数和生成请求元数据必须与总可见人数一致。尸体、
局部遮挡、过肩前景仍是可见人形；同一个人的肩背与脸不能重复计数；非现实
内心 Q 版叠层不计入真实人形。

以“林川目睹书童”为例：`characters=["林川"]`，黑衣人 3 名、书童尸体
1 具是功能人物，因此合同必须记录登记 1、功能 4、总可见 5。任何只锁
“林川 1 人”的提示词都会给模型留下漏画或乱补另外 4 个人形的空间，应在
编译或验证阶段被拒绝。

## 静态图片与视频规则分流

结构化合同可以共享事实，但不同媒介必须使用不同渲染规则：

| 生成类型 | 必须渲染 | 禁止渲染 |
|---|---|---|
| 静态图片 | 单个 `【定格状态】`、总可见人数、空间关系、静态机位与构图；首/尾相位只写结构化合同 | `【首帧定格】` / `【终点定格】`标签、同时出现 `【起点】`、`【单一主动作】`、`【终点】`的时间线及动作过程 |
| 视频 | `【起点】→【单一主动作】→【终点】`、一次运镜、人数与空间路径 | 多个主动作、无边界的过程扩写 |

静态定格状态优先采用 `freeze_state`、其次 `image_state`；没有这两个
显式覆盖时，首帧采用 `start_state`，其余图片及尾帧采用 `end_state`，只有
目标状态缺失才允许旧数据静态回退。合同必须记录结构化 `output`（媒体、
帧相位、时间策略）、`frame_target`、`frame_target_state` 与
`frame_target_source`；静态提示词仍统一使用 `【定格状态】`。显式字段
具有权威性，低优先级内容只能补缺。诸如“循声走到、放下包袱、躲到门板后”
的动作链不能进入图片提示词；图片只能写动作完成后可被一张画面同时观察到
的姿态、道具位置、视线和空间关系。

视频仍需严格保留首帧起点、单一主动作和尾帧终点，不能因为图片模板已简化
就丢失时序。Provider 不得擅自把图片合同转为视频动作，也不得把视频过程
压成含糊的静态描述。

## 参考图继承范围

参考图的用途由唯一 binding 和 `inherit_scope` 共同约束。身份参考图默认
及显式 scope 都只能在 `include` 中继承 `identity`，并必须在 `exclude`
中排除 `wardrobe`、`pose`、`background`、`props`、`prop_position`。
身份包括稳定脸部结构、年龄感、发际线、发型轮廓与发色，以及用户明确锁定
的身份标志；本镜服装、姿势、场景和道具位置服从更高优先级的镜头事实或
各自专用资产。

以下情况属于生成前硬失败：

- `inherit_scope.include` 与 `inherit_scope.exclude` 存在任一交集；
- 身份参考同时绑定 identity 与 wardrobe；
- 一张参考图同时承担多个互相独立的生产职责；
- 低优先级参考图试图覆盖本镜已锁定的服装、站位、道具或背景。

若用户希望使用身份图中的服装，应建立独立的服装参考资产/参考项，并让它
只承担 wardrobe binding。不得通过删除 exclude 或追加自然语言，让同一张
身份图在同一生成请求中兼任服装图。

## 空间关系与媒介一致性

`spatial_relations` 是当前镜头事实，必须保留到 v2.1 合同并渲染为明确的
“主体→关系→客体”。每条关系至少具有非空 subject、relation、object；
缺少主体或客体时必须阻止生成，不能让模型猜测。空间关系只在当前镜头
生效，不从身份图、全局故事或不匹配的连续性图传播。

媒介信息必须结构化。2D 与 3D 同时作为当前镜头的执行媒介时是硬冲突，
Provider 不得静默选择其一。“半写实 3D”应明确归类为 3D 漫剧渲染并标注
“非真人摄影”；半写实不等于 live action，也不能触发真人照片参考的默认
继承规则。

## 一次综合质检

每张图片只做一次综合质检，同时收集：

- 角色身份、性别和人数
- 可见角度对应的身份依据
- 登记人物、功能人物与总可见人数是否分别正确
- 物理与空间关系
- 2D/3D 媒介是否单一且与半写实/真人摄影边界一致
- 可读文字和时代事实
- 当前镜头提示词是否准确、简洁、无冲突
- 本次实际上传的参考图是否正确、完整、用途绑定一致

第一次失败后，只允许依据诊断修改当前镜头的提示词或参考图并自动重做
一次。第二次仍失败时，该项进入“等待人工”，系统继续生产不依赖它的
其他镜头；禁止原样重复调用和把失败补丁追加到其他镜头。

人工可以放行轻微表情或审美偏差，但不能强行放行身份、性别、人数、
物理空间或提示词/参考图输入合同错误。

## 推荐生产顺序

```text
导入小说/剧本源文档
  → 编剧影视化改编 + 一次综合逻辑审查
  → 人工锁定正式剧本
  → 人物候选与最终立绘
  → 简化/完整人物资产策略
  → 五维分镜 + 火柴人空间调度
  → 代表性 15 秒小样计划
  → 关键帧
  → 首尾帧视觉质检
  → 一次付费生产确认
  → Seedance 默认 4 路并行
  → 视频与交付质检
```

批量导入的解析稿只是源素材，必须经过编剧总闸门，不能直接成为正式
剧本。正式图片调用付费 API 时必须携带真实参考图；初次人物探索没有
身份参考时，只允许走 Codex 订阅通道，不允许 Seedream 或 OpenAI 图片
API 退化成纯文字生图。

## 《大明》重制原则

旧《大明》项目作为历史证据保留，不再在原项目上叠加修复规则。重制时
新建独立项目/版本，重新导入源文档，并按上述流程从编剧总闸门开始。
不得复制旧项目的待审核质检观察、一次性修复补丁、失败图片或旧标准
快照；只迁移用户明确锁定并再次确认的人物/世界事实。
