# 空间前置生产架构（正式版）

2026-07-29 定稿。这不是对旧流程的修补，而是按「以终为始」重排的自洽产线：
**每一阶段的输出都是下一阶段的已验证输入；空间是贯穿全程的唯一几何真相；
钱只在所有免费闸门全绿后才出门。**

依据：《长夏记事》EP1 从 v1 到 v7 的全部实付学费
（问题总账见 PRODUCTION_INCIDENT_LEDGER.md，验收标准见 END_TO_START_QUALITY_CHAIN.md）。

---

## 一、为什么必须重排（旧流程的结构性矛盾）

旧顺序 `剧本→分镜→空间→关键帧` 的三个死结：

1. **分镜先于空间**：分镜写「大特写」时机位还不存在，空间调度事后按声明硬凑，
   矛盾率实测 33%；景别与站位互相指责，同级熔断。
2. **场景没有几何真相**：单角度概念图只锁得住同方向镜头。关键帧各画各的房间
   （v6：6/8 镜出现换布景级跳变——香炉消失又冒出、外袍变坎肩、窗凭空出现）。
3. **空间一变，视线逻辑没人重推**：纱幔窗从「左后方」挪到「正前方」后，
   「她三十秒没察觉两米外的人影」不成立，发现拍点穿帮（v7 用户发现）。

## 二、新流程（自洽链）

```
剧本(信息状态声明)
   ↓
空间事实源                 ← 本次落地
   ├─ 720°全景母版          expand_scene_views(幂等),分镜阶段自动前置补齐
   ├─ 四向静态视角          main/side/reverse/side_left,从全景链式切
   └─ 3D空间模型            书案原点/地标坐标/机位约定(yaw0=+Z=全景中心)
   ↓
分镜(以空间为参考)
   ├─ 景别容量四门禁        大特写画不出全身(897794c)
   ├─ 时长下限≥4s           Seedance硬约束,fail-closed 指回分镜
   └─ 视线逻辑校验          「迟到的发现」穿帮警示 ← 本次落地
   ↓
空间调度(blocking)
   ├─ 3D机位按声明景别摆位  (35cd36d)
   └─ 朝向分相位            facing_start/facing_end,首帧禁带尾帧视线
   ↓
关键帧(串行链式)
   ├─ 背景=全景机位切片      v360确定性投影,零成本零漂移 ← 本次落地
   ├─ 态N锚态N-1            并行生成=各画各的房间,禁止
   ├─ 道具尺度               scale_reference 画面内参照物,三层防护
   └─ 闸门I                  相邻帧对比QC+合同核验,block清零才放行
   ↓
视频(预算分层,fail-closed)
   ├─ 迭代=mini 720p(45/段)  vip需 video_final_confirmed,否则拒发
   ├─ 提示词=起止视线过渡     「起点X→终点Y,中段连续过渡,不看镜头」
   └─ 下载数真实帧数          容器Duration会骗人(截断不报错)
   ↓
拼接交付
   ├─ concat滤镜             -f concat 静默丢帧,禁止
   └─ 成片时长/尺寸闸        不合格不出门
```

## 三、本次落地的平台件（全部在主分支,带测试）

| 件 | 位置 | 作用 |
|---|---|---|
| `pano_slice.py` | aifos/ | 全景→本镜机位透视切片(v360),坐标约定 yaw0=+Z |
| `_scene_slice_for_shot` | director | 关键帧场景参考优先用机位切片,回退四向静态 |
| `_ensure_space_first_scenes` | director | 分镜阶段第一步:自动补齐全景母版(config: space_first) |
| `_require_scene_views` | director | 帧链闸门:无全景不出帧(config: require_scene_views) |
| `awareness_sightline_issues` | spatial_blocking | 「迟到的发现」穿帮警示,写进 blocking.validation |

| 预算闸门 | dreamina | vip fail-closed / 时长下限 / --ratio / vip反选 |

工作区开关（workspace/config.json defaults）：
`space_first=true, pano_slice=true, require_scene_views=true`

## 四、新一集开拍的标准动作序（给下次干净跑）

1. `produce` 到分镜——空间前置自动生成全景+四向（零积分，codex）
2. 检查 blocking 的 `awareness_warnings`——有警示先改分镜再往下
3. 关键帧出图（自动带机位切片参考）→ 闸门 I 审查 → block 清零
4. mini 720p 全片（45/段）→ 拼接闸 → 交付测试版
5. 用户确认 → 同关键帧改 vip 1080p（165/段，需确认标记）出正式版

预期成本结构：一集 8 镜 = 测试 360 + 正式 1320 = **1680 积分封顶**，
所有试错都发生在零成本层（EP1 实测 v7 轮：闸门三轮 62 个 agent 审查，
修帧 6 次，视频只出了一次）。

## 五、明确不做的（防止缝缝补补回潮）

- 不再用文字禁令去补空间问题——空间问题一律回空间事实源解决
- 不再在视频层发现静态可判的问题——那是闸门 I 的失职
- 不再并行生成帧链关键帧——串行是结构要求，不是性能取舍
- 不再让任何「合同没写的字段」靠模型自由发挥——欠定义字段进合同或进闸门
