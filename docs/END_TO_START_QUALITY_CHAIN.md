# 以终为始：成片验收标准反推的质量链

日期：2026-07-29。本文回答三个问题：成片必须满足什么（终点）；每一条标准由哪个
上游阶段保证（反推）；每一类失败在哪一层就能**免费或便宜地**拦住（闸门）——
视频是全链条唯一按条收费的环节（mini 45 积分/段，vip 165/段），
**任何能在文本或图片层发现的问题，到视频层才发现就是纯浪费**。

## 0. 本次实测的浪费账（教训依据）

## 1. 终点：成片验收标准（唯一的「终」）

一部可交付的成片必须同时满足：

- **A. 连贯性**
  - A1 帧链：同场内镜 N 尾帧 = 镜 N+1 首帧（同一张图，不是「相似」）
  - A2 视线/朝向：单向过渡，无中途反向；跨镜视线承接（上一镜结束看哪，下一镜开始看哪）
  - A3 场景零漂移：陈设种类与数量、家具款式、纱幕材质跨镜恒定，不长出新东西
  - A4 身份恒定：同一张脸、同一套服装、同一支发簪，不变脸不换装
- **B. 物理逻辑**
  - B1 道具尺度正确且恒定（两指可捏的铃不得在任何一帧变大）
  - B2 动作因果有序（先触、再捏、再握；不得跳步或倒序）
  - B3 空间关系自洽（人影在画面左，望向它的视线也必须向左）
  - B4 与家具/身体的接触点连续（手放在案上就一直在案上，除非动作明说离开）
- **C. 无漂移**
  - C1 色温/光位/光比全片一套，不得逐镜变暖变暗
  - C2 画风恒定（写实不得中途变插画）
- **D. 技术规格**
  - D1 分辨率=声明档位（1080×1920），真实帧数完整（5s@24fps≈121帧/段）
  - D2 时长=分镜声明（±0.5s），拼接零丢帧
  - D3 无字幕、无水印、无画面文字

## 2. 反推：每条标准由哪一层保证

```
成片 ← 拼接 ← 视频段 ← 首尾帧(关键帧) ← 帧合同 ← 分镜+空间调度 ← 剧本+圣经
 D2     D1,D2    A2,B2      A1,A3,A4,B1,B3   全部A,B,C     A2,B2,B3        B1
```

原则：**每条验收标准向上找到「最早能以文本或图片形式被检查」的那一层，闸门就设在那里。**
视频层只验证「运动本身」——两帧之间的过渡是否自然。除此之外视频层不承担任何检查职责，
因为凡是静态可判的（身份、尺度、站位、光色、陈设），首尾帧上全都判得了。

## 4. 预算档位规则（用户已定，平台待强制）

| 场景 | 档位 | 单价 |
|---|---|---|
| 一切迭代验证（连贯性/动作/物理） | `seedance2.0mini` 720p | 45 |
| 画质对比 | **只取 1 镜**上 vip 1080p | 165 |
| 用户确认后的最终成片 | `seedance2.0_vip` 1080p 全量 | 165 |

强制方式（已实现）：vip/1080p 提交必须带 `video_final_confirmed`，否则 provider 层
fail-closed 拒绝提交（宁可报错也不静默花钱）。用户在确认页亲手选高档
（quality source=manual）自动视为确认；auto 推出来的高档照拦。
批量管线可用 conf `allow_vip_without_confirmation` 显式开闸。

## 5. 尚未解决的结构性问题（按影响排序）

1. **repair_contract 死路**：Codex 升级链下达「修合同」指令，全仓库无代码执行它。
   合同类失败因此只能人工介入。
2. **提示词有效信息密度**：真正描述「这一帧长什么样」的文字只占 4.5%，
   参考图绑定文字被注入两次占 47%。去重已做一步，绑定去重待做。
3. **审核环节净压缩为零**：审核把合同压缩 58%，适配器又原样加回 2019 字，
   白付一次 Codex 调用。
4. **空间图前置架构**（剧本→空间→分镜→关键帧）未落地——它是 A3/B3 的根本解法：
   陈设与站位一旦有了唯一的空间事实源，漂移就从「靠 QC 抓」变成「无从发生」。

## 6. v6 不合格复盘（2026-07-29，27 agent 逐帧审查，6/8 镜 fail）

**主导失败模式：镜内场景重生成跳变。** 镜1/2/3/4/6 在段内某一刻整套布景被替换
（香炉消失又冒出、案上书册全部重排、窗和盆栽凭空出现、外袍从有袖变无袖坎肩、
发簪从镂空雕花变串珠纺锤）。根因不在视频模型：**九张关键帧是并行生成的，每张
各自发明了一套房间细节**——帧与帧的接缝相同（同一文件），但段内要从房间A morph
到房间B。旁证：唯二 pass 的镜5/镜8 的端点恰是后来串行锚定重画的态5/态6。

**独立硬伤：视频模型压过关键帧视线。** 镜7 后 40% 时长头朝左、眼珠向右瞟，
叙事拍点失效。关键帧需「双眼虹膜朝向XX、严禁偏向XX」级硬约束。

**闸门修正：**
- 闸门 T 新增：帧链关键帧必须**串行**生成（态N 锚态N-1 + 场景母版），并行生成
  即违规；提示词必须含「本场固定陈设清单」与负面清单（严禁出现XX）。
- 闸门 I 修正：验收必须**逐对相邻帧**比对陈设/服装结构（袖型领型）/发簪形制；
  只查身份/光位/道具尺度不够——粗验九态全过、细审 6/8 fail 就是这次的教训。
- 本次审查本身就是闸门 I 的正确形态，只是执行晚了（视频钱已花）。下轮先审后花钱。

## 7. v7 复盘补充:空间重排必须重推「谁能看见谁」(2026-07-29,用户发现)

全景重排把纱幔窗从人物「左后方」挪到「正前方」后,原分镜的信息状态失效:
人影若从镜1就站在她正前方两米、逆光剪影,她整理卷册三十秒毫无察觉不成立;
且镜1已把人影亮给观众,镜7的「发现」拍点同时失效。

**修法(叙事侧)**:开场窗空着,镜2-6近景期间人影在画外到来,镜7后拉揭示
——人物与观众同时发现,惊疑成立(悬念结构替代穿帮的全知结构)。

**闸门推论(平台侧,待做)**:blocking/空间变更后必须重推视线逻辑——
剧本的 information_state 声明「X 未察觉 Y」时,空间事实必须满足
「Y 不在 X 的视野内」或「有遮挡/注意力理由」;否则 fail-closed 打回。
这属于空间图前置架构(任务#6)的信息状态校验环节。
